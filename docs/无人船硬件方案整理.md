## 一、产品路线

### 1. 打窝船

- 遥控版：遥控驾驶及打窝投料。
- 定位版：增加 GPS 定位导航。
- 高阶版本：增加摄像头等功能，具体定义待确认。
- 可选用途及设备：救生圈、探鱼器等。
- 以单片机控制为主，基础版本不需要 ROS 2 / SLAM。

### 2. 保洁船

- 第一阶段：水面保洁，清理水面垃圾与浮萍。
- 第二阶段：探索水下刷洗、清淤等作业，具体机构与回收方式待设计。
- 单片机负责实时控制；按智能作业需求评估 ROS 2 / SLAM 及外部计算。

### 3. 水下船

- 有线方案：岸端有线控制。
- 无线方案：通信方式和适用范围仍需验证。
- 应用方向：水下观察、巡检、作业等。
- 传感器、摄像头、耐压舱体及自主导航方案待进一步确定。

## 二、水面船控制板方案

图中标题：无人船一体控制板 · GPS + 地磁方案。

主要组合：STM32 + HMC5883L + L298N，搭配鱼鹰 P4C5 核心板及 USB 4G。

### 1. 模块职责

- STM32：读取 GPS 与地磁数据，运行 FreeRTOS，承担航向 PID、自动返航及左右电机控制。具体型号待选。
- HMC5883L：三轴地磁传感器，仅地磁，无 IMU；安装位置需远离功率回路并进行磁校准。
- GPS / 北斗模块：提供位置数据，具体型号待选。
- 鱼鹰 P4C5：图中规划 P4 负责视频采集及 H.264，C5 提供 Wi-Fi / BLE；具体板卡、接口与软件支持需核实。
- 摄像头：计划通过底板引出的 MIPI-CSI 接入，型号待选。
- USB 4G 模块：通过 USB Host 接入，模块、固件适配及供电待确认。
- L298N：双 H 桥控制左右两台有刷推进电机，电流能力及散热需核算。

### 2. 数据与控制流

- GPS / 地磁 → STM32 → PWM 与方向信号 → 电机驱动 → 左右推进电机。
- STM32 ↔ UART ↔ P4C5：交换遥测数据与控制指令。
- 摄像头 → P4 / H.264 → USB 4G → 移动网络 → 中转 / P2P → 手机或电脑。
- 视频目标为 720P；帧率和端到端延迟待实测。

### 3. 电源规划

- 3S 电池：按满电 12.6V 核算。
- 电机功率支路：直接接 L298N VS，需核对电机电压、堵转电流及驱动压降。
- SCT2450：规划降压至 5V，具体选型待确认。
- AMS1117-3.3：规划为地磁供电，需核对器件及模块输入要求。
- 主控 3.3V DC/DC：待选，用于 STM32 / P4C5，最终按板卡电源要求确定。
- 4G 模块供电：依据具体模块规格补充，尤其要核对发射瞬间峰值电流。
- 逻辑与驱动分区，规划回流路径并验证电机干扰。

## 三、初步评审与待确认事项

本节为建议，不代表原图已经实现或验证。

### 1. 导航可靠性

GPS + 地磁可用于基础导航原型，但无 IMU 时缺少倾角补偿。船体横摇、纵摇以及电机和电源线磁场均可能影响航向。GPS 位置不能在静止时直接提供可靠朝向。

需先明确定位误差、返航精度、风浪及低速运行条件，再决定是否增加 IMU，以及是否将磁力计远离主板功率区域安装。

### 2. 电机驱动匹配

L298N 压降与发热较大，不能仅依据“双路有刷电机”确定选型。先取得电机额定电压、运行电流和堵转电流，再核对驱动及散热能力，并评估合适的 MOSFET 驱动方案。

### 3. 视频联网链路

需要通过具体板卡验证摄像头驱动、H.264 编码、USB 4G 联网及视频遥测并行能力。720P 是目标而非实测结果；远程操控还需要评估抖动、断线重连及端到端延迟。

### 4. 安全控制边界

建议 STM32 保留最终电机控制权，P4C5 只提交指令，避免视频或联网系统故障直接影响底层控制。

需要定义以下状态及动作：

- 通信失联：根据导航有效性决定等待、停机或返航。
- 电池低电量：区分预警、返航阈值及保护阈值。
- GPS 丢失或位置异常：限制依赖定位的自动动作。
- 地磁异常：避免依据不可信航向持续推进。
- 上层系统重启：底层控制进入明确的安全状态。

不能无条件采用“失联立即返航”；定位或航向失效时，自动返航可能带来额外风险。

### 5. 水下产品边界

常规 GPS、Wi-Fi 和 4G 不能直接作为水下产品的可靠定位与通信方案。需单独选择线缆、浮标中继或其他技术路线。可以复用部分控制软件，但不能直接复用水面船的全部通信与导航架构。

## 四、结论

产品路线方向清楚，控制板目前属于待选型与实测的水面船原型方案。

建议保留“STM32 管运动控制，P4C5 管视频联网”的职责划分。落地前的关键条件是推进电机与驱动匹配、导航可靠性、视频链路验证和故障处理规则明确。
