# 双主控资源预算与候选引脚

核查日期：2026-11-18（Rev E）。适用：现有统一主板的增量设计；不是生产引脚表或硬件测试报告。

## 当前结论

按 STM32F407VET6（LQFP100）候选 + 所提供资料中的 ESP32-P4C5 88 脚核心板，所列接口已有无重复占用的条件候选分配；P4需增加摄像头控制扩展器，已无空闲通用GPIO。用户称 P4C3，与资料中的 P4C5 尚待核对实物。已确定新增 P4 SD 卡、删除独立温度模块、雷达走 UART 并继续连接 P4。深度、LED、五路驱动 PWM、CAN 与下载恢复入口均保留。

结论有前提：五个超声波采用 RS485，暂按不同地址、兼容协议且可轮询共用一路总线，与 BMS RS485 分开；声纳暂按一路 UART 预算；摄像头按保留USB UVC并新增/明确MIPI CSI与8bit DVP共三种接口预算，水下线缆改为独立RS485；“SDK”按SD卡、“CIS”按CSI理解。CSI/DVP复位与待机共4个控制脚迁移至I²C GPIO扩展器，同地址SCCB需隔离/多路复用。最终电平、带宽、DMA、PCB走线和供电未验证。

## STM32F4 预算

候选 STM32F407VET6：168MHz Cortex-M4、单精度 FPU / DSP，82 GPIO、6 串口（4 USART + 2 UART）、3 I²C、2 CAN。

成品IMU模块使用用户提供的《IMU模块原理图.pdf》第1页P1接口：P1-7 SCL接PB6，P1-6 SDA接PB7，P1-4接可断开的5V，P1-3/5接GND；P1-1 D3、P1-2 D1、P1-8 3.3V本版NC。模块载板有U3 RT9013-33GB将5V降为3.3V，R4/R5各4.7k把I²C信号上拉至3.3V。模块内部传感器型号、I²C地址、寄存器协议与速率待匹配手册确认；本版不占额外业务UART。

模块USB调试需先断开主板5V供电并协调I²C访问，避免USB与主板5V互相供电；I²C信号连接还须核对双方断电时的反灌路径。P2 UART与板载CH340X共用信号，外部MCU TX接入前须解决与CH340X TXD共驱动的问题。

## 双路 5V、PWM 与舵机接口（Rev E）

- 保护后的 6S 输入分给两只 SCT2650STER 候选：U901 输出逻辑 +5V，U903 输出 +5V_SERVO；共地、输出不得并联。U902 保留从逻辑 +5V 降至 +3V3 的连接。用户写 STC2650，采购型号仍待核对。
- J401 合并原五路 PWM，针序：1=逻辑 +5V、2=GND、3=PWM1_OUT、4=PWM2_OUT、5=PWM3_OUT、6=PWM4_OUT、7=PWM5_OUT。R401–R405 各100Ω，信号3.3V；5V仅供已核定的小负载/参考，禁止反灌，不是电机功率输入。
- J407 / J408 各三针：1=+5V_SERVO、2=GND、3=SERVO1_OUT / SERVO2_OUT。PA6#31 / PA7#32 采用 TIM3_CH1 / CH2、AF2；R407/R408各100Ω串联，R409/R410各100k下拉，C407/C408各100nF旁路。
- TIM3 两通道共享周期，可独立于原 TIM1/TIM9 驱动 PWM 配置。舵机型号、3.3V输入阈值、周期/脉宽、安全状态、运行/堵转电流及回流须确认；旁路电容不能代替瞬态储能设计。
- SCT2650 Rev1.3 的5V/500kHz外围作为候选：53.6k/10.2k反馈、RT200k、L7.8µH、4×47µF输出、33.2k串3.3nF补偿、22pF默认DNP。EN接保护后输入；6S截止由BMS/系统另行闭合。输入保护、两路负载预算、温升、环路和阶跃均未实测。
- P4 UART下载已有 TP701 TX / TP702 RX / TP703 EN、BOOT与RESET按钮；USB调试仍为逻辑口。C5的4/5/6/7/82焊盘在整板保持NC，下载电路未引出；P4与C5固件分别烧录，不能按C3套用。

## STM32 CAN1 与 ESP32-P4 模块

用户称通信主控为 ESP32-P4C3；所提供说明书和厂商仓库均为 ESP32-P4C5。当前按 P4+C5 的 88 脚模块资料配置，模块焊盘号不能与裸芯片脚号互换，实物型号和修订确认后才能冻结。P4 侧候选 GPIO20 / pad29 为 TWAI0_TX，GPIO21 / pad30 为 TWAI0_RX，另加 3.3V CAN 收发器；本版只分配 TX/RX 两个 GPIO，不额外预留 STB 控制脚。

F4 沿用 CAN1，不新增第二路：PD1/pin82（AF9）CAN_TX→U2.1 D，PD0/pin81（AF9）CAN_RX←U2.4 R。U2 为 SN65HVD230D 候选，3 VCC→3.3V、2 GND→地、7 H→CAN_H、6 L→CAN_L、8 Rs 经 R201 0Ω→地、5 Vref NC。C201 为100nF；PD6保持NC。J201针序为1 CAN_H、2 CAN_L、3 GND，不提供电源。

P4侧TWAI经另一收发器接共用经典CAN，USB-CAN以短支线并联。双方使用兼容位时序、报文ID与协议，控制/心跳优先、日志限速；主机断开不影响双MCU既定通信。视频不走CAN，F4首次下载/断点用SWD，P4保留USB Serial/JTAG与BOOT/RESET恢复入口。

拓扑按F4和P4侧为固定总线端点，各跨H/L接120Ω，USB-CAN关闭内置终端；F4 R202当前默认DNP，实际装配须按最终主干选择，不能未配终端就开始联调。接口保护/隔离、共模及线缆待核对。GPIO预算为29连接+1预留，UART使用5/6。

## 五个 RS485 超声波与 F4 算力

USART3 PD8/pin55 TX、PD9/pin56 RX 均用 AF7，PD10/pin57 为普通 GPIO，共控 U4 的 DE 与 /RE。低接收、高发送；默认下拉保持接收，发送时须在 USART TC 后切回接收，具体换向等待按收发器和模块时序确定。三脚替换原 PA8/PC9/PD5，功能 GPIO 预算不增加。

五个模块暂按同一条独立半双工 A/B 总线预算，与 BMS 的 USART2/U3/BMS_A/BMS_B 分开。必须确认模块具有不同地址、兼容协议且可受控轮询；RS485 本身不保证可寻址，也不等于 Modbus。地址不可改或模块持续主动抢发时，需要重新设计，不能直接并联。

U4 为 ADI MAX3485ESA+ 候选，1 RO→USONIC_RX、2 /RE与3 DE→USONIC_DE、4 DI→USONIC_TX、5 GND、6 A→USONIC_A、7 B→USONIC_B、8 VCC→3.3V。R513 为10k方向下拉，C501为100nF去耦，R514为可选120Ω终端，默认DNP。

J510–J514 暂为 A/B/GND 通信口，模块另供电，电压与电流尚未确定；收发器3.3V不代表探头电压。参考地、供电回流、屏蔽和隔离按线缆核定。采用总线主干与短支线，避免五条长星形支路；终端只按物理两端配置并检查模块内置终端。偏置、ESD与浪涌/隔离待定；MAX3485的开路接收保护不等于已保证终端空闲或短路时确定电平。

I2C1 留给 IMU，I2C2 留给深度，I2C3 释放。USART1/2/3 与 UART4/5 共用5/6；AIS使用UART5（PC12#80 TX / PD2#83 RX，AF8），USART6（PC6/PC7）仍为备用候选，具体 DMA 与额外控制脚未冻结。雷达沿用当前 P4 归属。

算力结论仍是工程判断：模块内部完成测距并输出距离时，F4执行轮询、滤波、姿态/控制和安全逻辑，可继续当前设计。视频、雷达数据在P4/上位机，不包含五路原始回波处理或声纳成像。用非阻塞状态机、接收中断/必要时DMA及超时管理，按模块手册安排错峰发射，避免声学串扰；定型时验证采样率、总线带宽、控制循环最坏执行时间、抖动和故障恢复，不编造CPU占用率。

| 功能 | 候选资源 | 通用GPIO预算 |

| UART激光雷达 | HP UART1，GPIO12/13；电气层待定 | 2 |

| 2.4GHz模块 | SPI2 GPIO7–10；IRQ/EN为GPIO11/5 | 6 |
| microSD | 外部SDMMC slot0，GPIO39–44，CD为GPIO45；非UHS 4bit | 7 |
| 水下线缆RS485 | HP UART3 GPIO28 TX / 29 RX / 30 RTS(DE)，模块pad55/56/57 | 3 |
| CAN | TWAI0 GPIO20 TX / GPIO21 RX，另加收发器 | 2 |
| CSI与摄像头管理 | GPIO22 SDA / 23 SCL，共用SCCB/I²C；GPIO48 CSI_XCLK | 3 |
| DVP 8bit | D0–7：GPIO0/1/4/32/33/46/47/49；HREF50、VSYNC51、PCLK52、XCLK53 | 12 |

| 水泵控制 | GPIO31/pad58 PUMP_EN → 外部功率驱动 | 1 |
| USB Serial/JTAG | GPIO24 D− / GPIO25 D+ | 2 |
| **条件合计** | 与88脚配置数据的42条候选用途一致 | **42** |

49个外露P4 GPIO = 42个分配 + 2个内部共享（GPIO6/54）+ 5个启动/恢复（GPIO34–38），无空闲通用GPIO。GPIO14–19在模块内部接C5 SDIO、未外露；不能重复使用。内部C5为slot1是依据连接作出的推导，仍须固件确认。专用CSI/USB差分脚不重复计入GPIO预算。

此分配必须增加I²C GPIO扩展器：CSI_RESET、CSI_PWDN、DVP_RESET、DVP_PWDN至少4个慢速输出；原CSI的GPIO46/47改给DVP。扩展器与两颗摄像头共用GPIO22/23总线。同地址传感器需I²C隔离/多路复用，不能直接并联；不默认用PWDN就能隔离SCCB。扩展器型号、电压、上电默认态、传感器复位/时钟/供电顺序和esp_video初始化适配待定。扩展器端口号不能直接填作P4 GPIO号；全部12个DVP高速信号直接连接P4。

DVP选LCD_CAM路径，避免使用与CSI共享ISP接入的ISP DVP路径。官方驱动以GPIO Matrix路由8bit数据、PCLK、VSYNC、DE(HREF)和XCLK；XCLK须满足源时钟整数分频及传感器要求，暂不承诺20/24MHz。GPIO0/1已占用，不能再接32kHz晶振；GPIO4为DVP_D2，不能同时用于外接GPIO JTAG。USB Serial/JTAG下载入口仍保留。此方案不保证USB、CSI、DVP同时采集/编码/写卡的性能，分辨率、格式、帧率和驱动兼容性须联合验证。

USB摄像头专用模块pad48 DM / pad49 DP，与USB下载pad50/51（GPIO24/25）分开。GPIO3使能受保护的5V VBUS开关，外部下拉默认关闭；GPIO2接低有效过流反馈并按开关要求上拉。CSI专用差分为模块pad41–46。SD卡使用GPIO39–45；pad66/VDDO4及固件电压配置未确认前不得假定可直接接线。

P4本次使用3路HP UART：雷达UART1、外部通信UART2、水下UART3。芯片有5路HP UART与1路LP UART，但控制器剩余不代表还有空闲引脚；恢复测试点GPIO37/38不算可任意挪用的运行接口。

水下线缆独立于F4的BMS和超声波RS485。暂按两线半双工，UART3的RTS共控收发器DE与/RE，外部下拉默认接收，使用UART_MODE_RS485_HALF_DUPLEX并禁用RTS/CTS硬件流控；换向、缆长、波特率、终端、参考地、隔离/保护和穿舱口待定。当前预算只覆盖控制/遥测，视频回传链路另行确定。

LED保持STM32 PB8#95 / TIM10_CH1，独立于五路驱动PWM。水泵为P4 GPIO31的逻辑使能，必须经外部功率驱动；高有效与下拉默认关闭仅为候选，按水泵用途确定失联、复位和故障安全状态，不能将GPIO直接接水泵。

AIS使用F4 PC12#80 / PD2#83 UART5 AF8。仅分配逻辑TX/RX；实际接口可能需要电平转换或收发器，方向、协议、波特率和供电待AIS模块资料确认，不默认RS422/RS232/RS485或Modbus。原理图用虚拟跨页端口P_AIS表示，物理连接器未定。

## 定引脚前的硬约束

1. F4具体料号、P4C3/P4C5实物型号及核心板修订要锁定。当前资料对模块pad66电源定义存在差异，不能直接认定为3.3V输出；需核对VDDO4、核心板电路和P4芯片修订。裸芯片pin54与模块pad66是不同编号体系。
2. 外部microSD选择slot0 / GPIO39–44，GPIO45检测；水下线缆已改为UART3 + RS485。内部C5占用GPIO14–19的SDIO，slot1归属仍需固件确认，不能按旧的裸P4预算把slot1直接分给外部卡。
3. 先锁P4的USB、专用MIPI、Flash/PSRAM、启动/复位与SD，再分配UART/SPI/TWAI/DVP脚。当前42脚已经用满，新增控制线需重新规划。USB Serial/JTAG可下载和硬件调试，但保留BOOT/RESET救援入口。
4. 外部SD卡以3.3V、4bit、20MHz非UHS模式为初期目标；VDDO4、pad66和slot0电压配置核定后才能连接。CMD/DAT上拉、ESD、去耦、插卡检测与供电峰值另设计；记录视频要验证持续写入、缓存、文件系统和断电恢复。
5. 雷达“串口”仅确定UART控制器，TTL/RS232/RS485、电平、单双向、速率、数据量未定；若需收发器方向/复位控制，另加GPIO。
6. 外部4G/LoRa端口按一块UART模块预算；USB HS已候选分配给摄像头，若再选USB4G，须评估Hub或额外控制器、驱动兼容性、共享带宽与供电，不能沿用本表UART连接或直接并接USB数据线。
7. 五个超声波已确定RS485；共享一条独立总线要求地址可区分、协议兼容且可受控轮询，不能默认Modbus。模块供电、电流、线长、终端/偏置/ESD/隔离与声学串扰待核验；主板通信口暂仅A/B/GND。声纳只按带处理能力的模块预算，原始回波处理另核算。
8. 资源够不代表采集、录像、显示、网络同时运行已达标。需要采样率、分辨率、帧率、码率与SD卡性能后安排DMA/任务/缓冲。CAN只负责控制、遥测与限速日志。

## F4 独立原理图 Rev E · 本轮同步

- [交互原理图](../design/原理图设计.html)：供电/去耦、时钟、启动/复位、SWD、CAN、BMS RS485、五路PWM七针口、两路舵机三针口、LED、深度I²C、超声波独立RS485及AIS逻辑端口。
- [100脚配置图](../design/STM32F407引脚配置图.html)：与原理图共用物理引脚数据，按提供的原理图符号方向排列。
- F4独立连接表含U1全部100脚、U4全部8脚、69个物理器件记录及3个跨页端口，共59个网络。R304默认不装；ADC保护与断电反灌未闭合。此处统计仅适用于F4单页，整板电路以第二页为准。
- U1 pin49→VCAP1→C108，pin73→VCAP2→C109，分别2.2µF到地，ESR<2Ω；依据ST DS8626 Rev12 p84表16、AN4488 Rev7 p9，实际页已渲染查看。阻容具体料号和有效容量仍待选型。
- U2依据TI SN65HVD230 p5；U3/U4依据ADI MAX3483–MAX3491 p7的MAX3485脚表，不代表已核验UMW替代料。参考PDF与页面渲染保存在tmp/f4_reference。
- F4单页P_IMU为IMU_SCL、IMU_SDA、GND跨页端口；整板接口连接成品模块P1及可断开的5V供电。第二页统一展示全板电路。HTML/SVG和连接表用于评审，不是可投板EDA工程。

- Camera Driver：CSI与LCD_CAM DVP独立资源、接口约束。https://docs.espressif.com/projects/esp-idf/en/stable/esp32p4/api-reference/peripherals/camera_driver.html
- ESP-IDF v6.1.1 LCD_CAM DVP实现：输入GPIO Matrix（128–143）、XCLK输出（340–347）、整数分频（386–407）。https://github.com/espressif/esp-idf/blob/v6.1.1/components/esp_driver_cam/dvp/src/esp_cam_ctlr_dvp_cam.c
- ST DS8626 Rev12：p66/67表9核对PC12 UART5_TX、PD2 UART5_RX均AF8；物理脚80/83见封装数据。
