## 1. 五路 PWM 的 100nF：连接已确认

| 网络 | MCU 引脚编号 | 并联电容 | 网表行号 |
|---|---|---|---|
| MOTO1_PWM_TIM3_CH1 | U19.31 | C146，100nF，对地 | 162 |
| MOTO2_PWM_TIM1_CH1 | U19.67 | C148，100nF，对地 | 163 |
| MOTO3_PWM_TIM2_CH1 | U19.30 | C145，100nF，对地 | 164 |
| MOTO4_PWM_TIM1_CH3 | U19.69 | C149，100nF，对地 | 165 |
| MOTO5_PWM_TIM1_CH2 | U19.68 | C147，100nF，对地 | 166 |

元件值见第5–7行，电容另一端见 GND 网络第189–200行。每个 PWM 网络仅含 U19 引脚、电容和测试点，没有串联电阻或缓冲器。MOTO1_PWM 至 MOTO5_PWM 在第95–96行定义为 Test-Point-0.5mm，并不是连接器。

工程判断：100nF 直接加载逻辑输出，会增加边沿充放电电流并减慢边沿；是否超出要求，仍取决于 MCU 输出能力、PWM 频率、外接驱动器输入门限和实测波形。不能将其解释为电机电源去耦，也不能套用一个网表中不存在的串联电阻来计算具体 RC 时间常数。新版建议预留但默认不装该电容，按外部驱动板接口和波形决定阻尼、保护及滤波参数。

## 2. 五个三针连接器：导出中未连接到 PWM、电源或地

第207–222行的 V1–V5、W1–W5、Y1–Y5 各只有一个引脚，分别属于 U14、U16、U18、U15、U17。因此这份导出内没有它们与上述 PWM 的连接，也没有它们与电源或地的连接。需回到原工程核实是否为占位、漏连、导出缺失或另有板外接线；不能由此推断实物一定相同。新版五路 PWM 接口应明确每路信号、回流地、电平及默认安全状态。

## 3. 电源反馈：连接异常需优先核对

- 第140行：$9N50410 = C13.1、R22.2、U12.2。
- 第184–186行：5V0 包含 C13.2、R22.1、R21.2。
- 第189–200行：GND 包含 R21.1。
- 第59行 R21 = 49.9K；第67行 R22 = 365k。

已确认的连接是：R22 从 5V0 接至 U12.2；R21 从 5V0 接地，而非从 U12.2 接地。若 U12 与此前 PDF 一致、为 TPS56528 且2脚是 VFB，则反馈下拉分压电阻缺失，R21 的上端连接有误。需按器件数据手册修正并核查；网络命名 5V0 不等于已验证稳压输出5V。

## 4. IMU 中断：名称不等于连接

第203行 PB5 网络只有 U22.12，没有 U19 引脚。若 U22 与此前 PDF 一致、为 MPU-6500，则 INT 在这份网表里没有接到 MCU，不能因为网络名为 PB5 就认为已连接。相比之下，IST8310 的 DRDY、RSTN 分别通过 R75、R74（0Ω）连至 U19.3、U19.4；不要混淆两颗传感器的中断线路。MPU 中断未接不代表 I²C 轮询必然不可用，但无法按此网表实现该中断路径。

## 5. 对新版方案的边界

本文件用于旧版连接证据，不代表新版已包含 ESP32-P4、双 MCU CAN 或水下以太网。新版继续按五路逻辑 PWM 外接独立驱动板设计。旧 U3 的连接为 I2C2_SCL/SDA、3V3、GND；旧 U4 则接 BAT_A/B、5V0、GND，不能视为用户新增的 I²C 温度接口。电源、连接器、IMU 中断问题应在复制旧电路前处理。
